# Agent notes

NixOS + Home Manager flake for three desktops and a home server. See `README.md` for the layout and `docs/` for usage.

## Applying changes

- System management uses `nh`, never `nixos-rebuild`. When suggesting how to apply changes, use:
  - `nh os switch` to build and activate
  - `nh os boot` to activate on next boot
  - `nh os test` to activate without adding a boot entry
  - `nh os switch --update` to update flake inputs and switch
- `nh` already knows where this flake lives (`programs.nh.flake` in `modules/nixos/desktop/base.nix`), so no path or `--flake` flag is needed.
- Do not run `nh os switch/boot/test`, `sudo` or reboots yourself. Tell the user what to run.

## Hosts

| Host | Machine | GPU | Notes |
|---|---|---|---|
| `97` | Desktop (dual boot Windows) | NVIDIA | gaming, ultrawide on DP-1 + 1080p on DP-2 |
| `dongmyo` | Laptop | AMD | power profiles, hibernate |
| `esa` | Work PC | Intel | three monitors, work setup |
| `homebox` | Home server | AMD iGPU | nixos-stable, ZFS, rootless Podman; no desktop modules. Deployed from a desktop: `nh os switch -H homebox --target-host mikkel@192.168.3.2`. Never run anything on it that changes it (no sudo, writes, restarts); read-only inspection over SSH is fine. |

- Host-specific settings go in `hosts/<host>/` (`default.nix` system, `home.nix` Home Manager, `hyprland.lua` monitors and rules).
- Shared settings go in `modules/nixos/common/` (system, every host), `modules/nixos/desktop/` (system, desktop hosts only) and `modules/home/` (Home Manager, desktop hosts).
- Shared modules switch on `my.*` options (`my.gpu`, `my.gaming.enable`, `my.work.enable`, `my.laptop`, `my.secureBoot.enable`, ...), not on hostnames. Prefer adding or reusing such an option over host checks. Options are declared in `modules/nixos/desktop/default.nix` and the modules that use them.

## Checking changes

- New files must be `git add`ed: flakes ignore untracked files, so an unstaged module is silently missing.
- `nix eval .#nixosConfigurations.<host>.config.<option>` to check a single value.
- `nh os build` (current host) or `nix flake check` (all hosts) to build without activating. The build also verifies the Hyprland config (`modules/nixos/desktop/checks.nix`).
- `nix fmt` to format (nixfmt-tree).

## Don't touch

- `hosts/*/hardware-configuration.nix`: generated by `nixos-generate-config`.
- `secrets/*.age`: agenix-encrypted. Ask before changing `secrets/keys.nix` or `secrets/agenix-rules.nix`.
- `flake.lock`: only update when asked (`nh os switch --update`).
- `backup/`: backup and restore scripts and path lists.
- homebox's domain and the home IP: never write them in the repo (code, docs, commit messages).
  The domain only lives in agenix and is read at runtime (`{$DOMAIN}`, env files); see
  `docs/HOMEBOX.md`. Never read a decrypted secret at evaluation time (it would end up in the
  Nix store).

## Style

- Comments explain *why*: the reason for a workaround, when it can be removed (e.g. an upstream issue), and alternatives that were rejected and why. Keep this up when changing such code.
- Update `README.md` or `docs/USAGE.md` when a change affects hosts, keybinds or everyday commands.
